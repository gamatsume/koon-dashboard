# koon-dashboard

Markdown ファイル群をデータソースとして読み込み、Next.js 製のダッシュボードに
表示するアプリです。データベースは持ちません。**フォルダと `.md` ファイルがそのままデータです。**

- **読むだけ**: アプリはファイルを読むだけで、書き込みは一切行いません。編集は普段お使いのエディタや Obsidian で行います。
- **フレームワーク**: Next.js (App Router, TypeScript, Tailwind CSS v4)
- **Markdown 解析**: `gray-matter`（frontmatter）+ `react-markdown` / `remark-gfm`（表・チェックリスト）

---

## すぐ試す

```bash
npm install
npm run dev
```

`http://localhost:3000` を開くとダッシュボードが表示されます。
初期状態では `sample-db/` のサンプルデータが読み込まれるので、**そのまま動きます。**

| ページ | 内容 |
|---|---|
| `/` | ダッシュボード本体 |
| `/views` | 表示のしかた（決まりの一覧。読むだけ） |
| `/settings` | `_view.md` を作る（ビューを選んでコピー／ダウンロード） |
| `/view/<フォルダ名>` | カード1枚を横いっぱいで表示（カードの見出しから開けます） |

---

## 自分のデータに差し替える

`.env.local` を作り、データフォルダの場所を指定します。

```bash
echo 'DASHBOARD_DB_PATH=/Users/yourname/Documents/MyDashboardData' > .env.local
```

未設定のときは `dashboard.config.json` の `dbPath`（既定は `sample-db`）を読みます。
相対パスも使えます（プロジェクトルート起点）。`~` から始まるパスも展開されます。

## ダッシュボードの仕組み

### フォルダ = カード

DB の直下にあるフォルダ1つが、カード1枚になります。**フォルダ名がそのままカードの見出し**です。

```
DASHBOARD_DB_PATH/
├── 今日のマスト/            ← 見出し「今日のマスト」
│   ├── _view.md            ← 表示設定（view: checklist）
│   ├── 2026-08-15.md
│   └── routine.md
├── 今週の目的/
├── 予定タスク/
├── サブスク・AI利用状況/
└── …
```

- 各フォルダ直下の `.md` を読みます。サブフォルダは読みません
- `README.md` と、`_` で始まる `.md`（`_view.md`・`_template.md` など）はノートとして扱いません
- 名前が `_` や `.` で始まるフォルダと、`.md` が1つも無いフォルダ（画像置き場など）はカードになりません

### 表示設定（`_view.md`）

フォルダに `_view.md` を置き、プロパティで表示を決めます。置かなければ「メモ」で表示します。
Obsidian からも普通のノートとして編集できます。

```markdown
---
view: table
width: 6
show:
  - plan
  - price
---

本文はダッシュボードに出ません。メモ欄として使えます。
```

| プロパティ | 意味 | 書かなかったとき |
|---|---|---|
| `view` | ビューの種類（下の表。日本語名でも可） | `note` |
| `width` | カードの幅。1〜6（横は6列ぶん。6で横いっぱい） | 種類ごとの既定 |
| `show` | カードに出すプロパティ名のリスト | 出さない（`table` だけは全プロパティを列にする） |
| `hidden` | `true` でカードを出さない | 出す |

設定に誤りがあると（`view` の綴り違い、`width` が1〜6以外など）、カードの上に理由が表示されます。

アプリ内にも同じ内容があります。

- **`/views`（ヘッダーの「表示のしかた」）**: 決まりの一覧。読むだけのページです
- **`/settings`（ヘッダーの「_view.md を作る」）**: ビューを選ぶだけで中身を作れます。
  コピーかダウンロードで受け取り、適用したいフォルダの直下に置いてください
  （アプリは書き込まないため手作業です）

### ビューの種類

| `view` | 日本語名 | 出すノート | 本文の扱い | 既定の幅 |
|---|---|---|---|---|
| `checklist` | チェックリスト | 全ノート（新しい順） | `- [ ]` / `- [x]` の行だけを集計（それ以外は出ない） | 2 |
| `habit` | 習慣 | 今日の分（マス目には全部の記録を使う） | `- [ ]` / `- [x]` の行だけを集計 | 2 |
| `document` | ドキュメント | 最新の1件 | Markdown を全文表示 | 2 |
| `quote` | 格言 | 日替わりで1件 | Markdown を全文表示 | 2 |
| `schedule` | 予定 | 今日以降と日付なし（日付の近い順） | 使わない | 6 |
| `feed` | フィード | 全ノート（新しい順） | 最初の1行だけ | 2 |
| `note` | メモ | 全ノート（新しい順） | 最初の1行だけ | 2 |
| `table` | 表 | 全ノート（タイトル順） | 使わない | 6 |

「新しい順」は、**日付があれば日付の降順、無ければファイル名の降順**です。
ファイル名から日付として拾えるのは `YYYY-MM-DD` の形だけなので（`2026_1019週` などは拾えません）、
日付を持たないノートもファイル名の降順で新しいものが上に来ます。
`schedule` だけは「次に来る予定」を上にするため、日付の**昇順**です。

### プロパティ

frontmatter は任意です。無くても動きます。次のプロパティは決まった役割を持ちます。

| プロパティ | 役割 |
|---|---|
| `title` → `name` → `subject` | タイトル（左ほど優先。どれも無ければファイル名） |
| `date` | 日付（無ければファイル名中の `YYYY-MM-DD`）。並び順と残り日数に使う |
| `url` | `http(s)` で始まるとき、タイトルが外部リンクになる |
| `source` → `from` | 出どころ（左ほど優先）。日付の横に出る |
| `author` | 格言の署名 |

それ以外のプロパティは、`_view.md` の `show` に書くとカードに出ます。
`table` は `show` が無ければタイトル以外の全プロパティが列になります（日付は `yyyy-MM-dd` で表示）。
ノートの詳細ページには、すべてのプロパティが出ます。

**frontmatter が壊れていてもクラッシュしません。** 生の本文として表示されます。

### 習慣（`habit`）

日付のファイル名（`2026-10-31.md`）のノートを1日ぶんの記録として読み、カードに次を出します。

- 今日のチェックリスト
- 連続で全部できた日数 / 全部できた日の合計 / 記録のある日数
- 直近17週間のマス目（その日の達成率で濃さが変わります）

```
習慣/
├── _view.md          view: habit
├── _template.md      今日のぶんのひな形
├── 2026-10-30.md     - [x] ストレッチ / - [x] 読書を30分
└── 2026-10-31.md     - [x] ストレッチ / - [ ] 読書を30分
```

チェックは Obsidian で付けます。**アプリは書き込みません。**

連続日数は、その日のチェックが**すべて**付いた日だけを数えます。
今日がまだ終わっていないうちは昨日から数えるので、朝に毎回 0日 とは出ません。

#### 今日のぶんを用意する

`_template.md` を置いておき、その日のノートを Obsidian で作ります。
アプリはデータフォルダに書き込まないので、用意するのは利用者側の仕事です。

```markdown
- [ ] ストレッチ
- [ ] 読書を30分
```


### 並び替え

カード上部の ⠿ をドラッグすると並び替えられます（⠿ を選んで矢印キーでも動かせます）。

- 並び順は**ブラウザに保存**されます。アプリは DB に書き込まないので、端末・ブラウザごとに別になります
- 並べ替える前は、上の表のビューの種類順 → フォルダ名順です
- 「並び順を元に戻す」で初期の順に戻ります

### カードを追加する

1. DB にフォルダを作る（フォルダ名が見出しになる）
2. `.md` を置く
3. 必要なら `_view.md` で種類を決める

コードも設定ファイルも変更は不要です。

## ディレクトリ構成

```
app/
├── page.tsx              ダッシュボード本体
├── views/                表示のしかた（読むだけ）
├── settings/             _view.md を作る
├── view/[folder]/        カード1枚のページ
├── db/[...slug]/         DB ノートの詳細
└── @modal/               ノートをモーダルで重ねるスロット
lib/
└── dashboard.ts          DB の読み込み、設定ノート、プロパティの扱い
components/
├── ViewCard.tsx          カード（ビューの種類ごとの表示）
├── NoteView.tsx          ノート1件の中身（単独ページとモーダルで共用）
├── Modal.tsx             モーダルの枠
├── SortableGrid.tsx      カードの並び替え
├── ViewSettingsBuilder.tsx  _view.md の組み立て
├── ThemeToggle.tsx       ライト／ダーク切り替え
└── RefreshButton.tsx     再読み込みボタン
dashboard.config.json     データの場所（dbPath）
sample-db/                サンプルデータ（DASHBOARD_DB_PATH 未設定時に使用）
```

## 注意

- **サーバーサイドでファイルを読みます。** ローカル、あるいは自分だけがアクセスできる環境での利用を想定しています。データフォルダの内容がそのまま画面に出るため、公開サーバーへそのまま置かないでください。
- ページはリクエストごとにレンダリングされます。ファイルを編集したら「↻ 更新」で反映されます。
